# D3 原生键鼠方案（Windows / ScarletNX）

修订：2026-11-01。接手先读 [KBM-HANDOVER.md](KBM-HANDOVER.md)；本次代码/实机方法评估见 [KBM-METHOD-ASSESSMENT.md](KBM-METHOD-ASSESSMENT.md)，历史逆向记录见 [KBM-RE-EVIDENCE.md](KBM-RE-EVIDENCE.md)。

**用户要求：只做原生键鼠。停止键鼠转 Npad、鼠标转摇杆、虚拟手柄，以及“悬停设焦点后合成 A”的方案；这些不作为保底、阶段性交付或失败后的退路。**

范围是 Windows 运行时；Android 需要单独确定输入接入点。本次修订包含方案/交接纠正、RE 探针修复和有限实机评估，没有修改、重建或替换运行时。现有安装和补丁仍含历史 A+ 实现，不能据本文宣称已经停用或完成原生输入。

## 1. 方向判断

**继续寻找 D3 自己的鼠标消息、世界点击和键盘动作入口，方向合理；“先做手柄映射，再补原生”不符合需求，停止执行。原生可行性仍待 D3 的实测证明。**

有价值的资产是运行时代码 dump、UI 对象注册表，以及 guest 调用桥。它们使后续调查可以针对真实对象和实际执行代码，但没有接通任何完整的原生鼠标操作。

以下旧结论作废：

- “D2R 做到了，所以 D3 一定有完整 PC 输入层”：只能作为研究假设。
- “保留了 LeftClickToMove 等字符串，所以只差函数地址”：字符串、资源和描述表不等于仍可执行的鼠标路径。
- “调用桥已跑通，所以可以直接调用菜单 handler”：目前只观察到几个空参数调用返回，没有可见业务效果；参数、上下文和线程归属仍待确认。
- “只成功 UI 就回退到 A+ 走位”：不符合用户范围；只能报告已验证的原生能力和剩余阻塞。

## 2. 当前证据与缺口

| 项目 | 当前证据 | 不能据此推出的结论 |
| --- | --- | --- |
| 历史 A+（0002） | 鼠标位置写左摇杆，鼠标按键写 A/B/X/Y/L | 不算原生移动、瞄准或 UI 点击 |
| 原生调用桥（0003） | 复制 CPU、独立 guest 栈，经 snx_lookup 执行；空参数 handler 调用曾返回 | 不代表已在正确的 UI 主线程、安全帧点或有效上下文运行 |
| UI 对象注册表 | 可由名字哈希查对象，游戏内记录约 19.3k 条目 | 不代表全部可见、可点击，或已有可靠父子链、遮挡和坐标变换 |
| LeftClickToMove / ActionBinding 等 | 字符串和描述数据保留 | 不证明动作分发仍存在并可启用 |
| UI 回调表 | 已枚举，历史 hook 观测中普通确认操作未命中 | 不证明真正鼠标事件必须走某个指定 VM 或该表 |
| 鼠标/键盘 HID | 当前导入和调用扫描未发现 main 消费相应状态 | 直接填 HID 鼠标环没有已验证的消费端，不作为主线 |
| 世界点击、UI hover/click、键盘动作 | 尚未闭环 | 原生键鼠尚未实现 |

2026-11-01 新实测确认：当前 fixed ELF 的 text、rodata 与运行时 dump 逐字节一致；此前“不一致”来自将 guest 地址按 `0x8000000` 而非 `0x8005000` 换算，错了 `0x5000`。撤回版本不匹配及其派生结论，沿用已核验的 ELF，并统一 guest/模块偏移。旧 hook 的 x64/guest ABI 和引用扫描覆盖问题也已确认，详见 [方法评估](KBM-METHOD-ASSESSMENT.md)。

## 3. D2R 参考的正确用法

[D2R 的 dm_cursor.c](https://github.com/d2r-mobile/d2r-mobile/blob/main/dm/host/dm_cursor.c) 有向 UI 根控件发送 InputMessage 鼠标事件、由游戏执行命中测试的实现；也保留了手柄光标和按键路径。因此只参考原生消息部分，不能整套照搬为本项目方案。

[D2R 的 dm_world.c](https://github.com/d2r-mobile/d2r-mobile/blob/main/dm/host/dm_world.c) 展示了调用游戏共享点击入口、指定目标并由游戏处理靠近交互的方法。但当前源码明确不把空地点按作为点地移动；它不能充当 D3 点地走位已可实现的证据。以上为 2026-11-01 核对的上游 main，D3 必须独立验证。

共享动作函数同时被手柄使用，不影响它成为原生键鼠的接入候选；判断依据是键鼠是否直接提供坐标、目标和鼠标/键盘动作语义，并交给游戏处理，而非是否生成了手柄按键或摇杆状态。

## 4. 唯一实施链路

```text
SDL 键鼠事件
  → 原生事件队列（位置、按下/抬起、滚轮、按键/文本）
  → 已确认的游戏 UI/输入主线程及安全处理点
      → UI：游戏自己的鼠标消息分发、命中、hover、点击、捕获/拖放
      → 世界：场景拾取/屏幕到世界转换 → 游戏移动、技能、交互动作
      → 键盘：游戏按键绑定/动作分发与文本输入
```

键鼠事件不转换为 Npad 按钮、左右摇杆或 Switch 触摸。物理手柄原有支持不是本任务新增键鼠链路。

Windows 运行时执行的是重编译 guest 代码；guest 地址不能直接当作宿主 C 函数指针。调用必须经过匹配当前版本的 dispatch/guest 桥，并确认 ABI、真实参数、对象生命周期、TLS、栈和返回约定。

## 5. 下一步顺序与判据

### P0 固定代码基线，确认执行线程与上下文

- 核对游戏 build id、code.dll 与运行时哈希；重取 g_mem / g_disp / g_code_lo 符号 RVA。
- 优先从当前运行时代码和指定控件定位 UI 根对象、事件入口及输入更新点；对象注册表用于缩小调查范围。
- 当前桥在通用 rt_poll 和 snx_svc 入口取队列，没有 UI 主线程筛选。先确认真实线程、TLS 和帧阶段，再允许有业务效果的调用。
- 确认目标函数 ABI、控件/VM 上下文、消息负载的内存映射及生命周期；记录真正返回、超限或查找失败，不能只以日志中的 returned 作成功依据。

验收：可复现地在已识别的目标线程执行一次参数正确、结果可核验的探针；空参数无效果返回不算完成。

### P1 接游戏自己的鼠标事件入口

- 从指定控件的事件方法、回调对象使用者及 UI 输入更新路径反查消息分发；先定位接口，再构造事件。
- 先只送 MouseMove，确认“继续”和“选项”产生不同且正确的 hover；再验证原生 down/up、滚轮与事件消费。
- 坐标须覆盖 SDL 客户区、实际游戏视口、黑边、缩放与游戏 UI 坐标系。矩形字段只作取证；注册表排序或手写矩形过滤不能替代游戏自身的完整命中规则。
- 直接调用带真实上下文的业务回调可用于定位，但不能单独证明 hover、事件捕获与原生点击链路成立。

验收：关闭键鼠转 Npad 和鼠标转触摸后，主菜单、暂停菜单、背包仍能按指针位置 hover/click，并由游戏正确处理遮挡、可见性和禁用控件。

### P2 验证世界点击，尽早启动调查

UI 有进展不能替代这一项，也不应等 UI 全做完才开始找世界入口。

- 定位屏幕拾取/屏幕到世界点、目标解析，以及游戏自己的移动/交互/定点技能命令。
- LeftClickToMove 和 UI_HUD_ClickPredicate 只作定位线索，先确认真实消费者、参数和玩家上下文；谓词本身不是移动命令。
- PowerCursorSetToOpenLocationNearCursor 接受 cursor 索引，不能直接塞屏幕 x/y。
- 禁止把点击目标转换成持续推杆、自动按 A 或宿主自行导航来替代原生入口。

验收：点击城镇两个不同空地点，松开鼠标后角色仍到达对应目的地；障碍处理遵循游戏原生规则；点 NPC/物品/出口能正确选择目标并完成交互；技能能使用鼠标目标。全程不生成 Npad 输入。

### P3 接键盘动作和文本

确认 ActionBinding 或等价动作分发的有效代码与绑定数据。Tab/I/M/1–4/Esc、修饰键、重复按键和按下/抬起按实际游戏绑定验证；不要预先宣称某套键位已经可用。文本输入单独验证字符/输入法路径。

### P4 路由与稳定性

游戏 UI、世界和运行时 F2 菜单之间按消费结果分发事件；菜单不穿透，UI 上点击不落到地面。处理失焦释放、窗口/全屏切换、对象销毁重建、存档/读档和暂停。

PC 布局只在验证发现当前 Console 布局缺少必要鼠标处理时考虑；布局资源存在本身不证明可直接切换成功。

## 6. 验收与交付边界

- 原生 UI：hover、按钮、滚轮、背包/技能页的必要拖放可用，遮挡与禁用状态正确。
- 原生世界输入：点地移动、点目标攻击/交互、技能指向可用，输入来自鼠标坐标/目标。
- 原生键盘：热键、按下/抬起、修饰键和文本输入可用。
- 路由：游戏菜单、F2、失焦不穿透、不卡键；1024×576 和 1280×720、窗口/全屏、黑边下坐标正确。
- 稳定性：持续操作 30 分钟，无重复点击、丢失抬起或坐标漂移。
- 输入链路证据：关闭键鼠生成的 Npad/触摸输入后仍通过；保留事件类型、线程、目标对象/世界点与动作结果日志。

只完成 UI 时，状态是“原生 UI 部分验证，世界/键盘未完成”。若关键路径受平台裁剪，记录缺失的代码/资源、已尝试的接口与剩余工作；不自动改交手柄映射，也不在证据不足时保证必然可行或断言绝对不可能。
